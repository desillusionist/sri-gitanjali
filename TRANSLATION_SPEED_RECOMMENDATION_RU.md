# Как ускорить второй перевод шлок

## Короткий вывод

**Рекомендую не заменять текущий LLM-перевод полностью.** Для Kīrtan Guide наиболее разумен двухэтапный план: сначала оптимизировать текущий LLM-поток так, чтобы переводы появлялись **по одной шлоке сразу**, затем при необходимости добавить **Google Cloud Translation Advanced с глоссарием** как быстрый optional-режим.

Это сохраняет лучший контроль над IAST-терминами и переводами в нелатинские письменности, не требует ключей в браузере и ощутимо улучшает восприятие скорости: пользователь видит первую готовую шлоку сразу, а не ждёт завершения всей песни.

## Сравнение вариантов

| Подход | Скорость и UX | Качество терминов / IAST | Ограничения | Вывод |
|---|---|---|---|---|
| **Текущий LLM, оптимизированный** | Первые результаты появляются по мере готовности; можно ограничить параллелизм 2–3 запросами | Самый гибкий: сохраняются текущие правила IAST/ISO 15919 и транслитерации в целевую письменность | Требует обращения к серверной модели; полный перевод песни всё ещё занимает время | **Рекомендуемый базовый путь** |
| **Chrome Translator API** | On-device; не требует серверного запроса после скачивания language pack | Нет контролируемого глоссария и отдельной логики для IAST-терминов | Экспериментален, ограниченная совместимость, Chrome desktop; не работает на mobile | Только optional fallback, не основа продукта |
| **Google Cloud Translation Advanced + glossary** | Обычно быстрый сервисный машинный перевод; легко обрабатывать по одной шлоке | Глоссарий даёт стабильные соответствия терминов; но потребует внимательно составить словарь для каждого языка | Нужны Google Cloud project, биллинг, серверные credentials и поддержка глоссария | Хороший второй этап при готовности подключить Google Cloud |

## Рекомендуемая реализация — сначала без смены провайдера

### 1. Немедленный показ перевода по шлокам

Вместо одного ожидания для всей песни клиент отправляет первый запрос для первой шлоки, затем поддерживает очередь следующих. Каждая готовая шлока отображается сразу, пока остальные показывают компактный loading state. Это решает главную UX-проблему — «ничего не происходит, пока переводится вся песня».

### 2. Умеренный параллелизм

Запускать одновременно **не более двух или трёх** шлок. Это сокращает общее время ожидания, но не создаёт всплеск запросов, не ухудшает стабильность и не перегружает серверный LLM-поток. Кэш остаётся прежним: при повторном открытии уже переведённые шлоки появляются мгновенно.

### 3. Приоритет видимой шлоки

Если пользователь раскрыл конкретную шлоку, она переводится первой. Остальные идут в фоне. Для Slideshow полезно заранее переводить текущую и следующую шлоки.

### 4. Лёгкий режим качества

Сохранить текущий строгий LLM-prompt для терминов, но ограничить одну операцию одной шлокой и запросить только чистый перевод. Это уменьшит число выходных токенов и риск неполного JSON, не отказываясь от правил транслитерации.

## Когда оправдан Google Cloud Translation

Google Cloud Translation Advanced имеет смысл добавлять, если вам нужны **предсказуемая низкая задержка** и отдельный машинный перевод для большинства шлок, а также вы готовы:

1. Создать Google Cloud project, включить Cloud Translation API и настроить серверные credentials.
2. Вести глоссарий с именами и терминами: `Śrī`, `Kṛṣṇa`, `Chaitanya`, `Mahāprabhu`, `kīrtan` и их целевыми формами для каждого языка.
3. Проверить результат на русских, украинских, китайских, тайских, хинди и бенгальских текстах, особенно на редких терминах.

Предлагаемый гибридный вариант: **Google Cloud переводит быстро, а LLM остаётся доступен как режим «Refine terminology» или как fallback** для шлок, где важны точная формулировка и письменность терминов.

## Почему не стоит делать Chrome Translator API основной функцией

Chrome Translator API действительно выполняет перевод на устройстве и поддерживает целевые языки Kīrtan Guide, но его поддержка ограничена Chrome desktop; на mobile API не работает. Также Chrome обрабатывает переводы последовательно, а перед первым использованием может скачивать language pack. Поэтому он полезен как прогрессивное улучшение для части desktop-аудитории, но не даёт единый, управляемый результат для PWA.

## Предлагаемый порядок работ

1. **Сейчас:** изменить текущую LLM-интеграцию на очередь «шлока за шлокой» с ранним показом и параллелизмом 2.
2. **После UX-проверки:** добавить статусы «Переводим 3 из 8» и кнопку повторной попытки рядом с отдельной шлокой.
3. **При необходимости:** внедрить Google Cloud Translation Advanced через сервер, с глоссарием и переключателем провайдера только для владельца сайта.
4. **Опционально:** добавить Chrome Translator API как desktop-only fallback с прозрачным сообщением о доступности.
